1. 문제: 시스템은 성공했는데, 결과는 0개실제 업무 경험

교육 영상의 STT 데이터를 CLOVA Speech로 구축하던 중, 처리 상태는 SUCCESS인데 추출 문장이 0개인 장애를 겪었습니다. 시스템은 원인도 해결 방법도 알려주지 않았고, 영상·오디오·채널·포맷을 직접 비교하며 원인을 좁히는 데 약 2시간이 걸렸습니다. 해결 후에는 같은 조치를 약 100개 파일에 수동으로 적용했고, 입력 용량 제한 때문에 MP4를 MP3로 바꿔 재업로드하는 작업도 반복됐습니다.

Pain Point 정의. 가장 큰 비용은 실패 자체가 아니라 "실패했는데 실패라고 알려주지 않는 것"이다. System Success(파이프라인 통과) ≠ Business Success(쓸 수 있는 STT 결과). 이 차이를 사람이 직접 진단해야 했다.

2. 해결: troubleshooting 과정을 제품 workflow로

Diagnose포맷·디코드·크기·track·codec·채널 수 + 채널별 신호 측정
→
ExplainReady / Review / Not Ready와 원인·영향·조치
→
Fix근거가 명확할 때만 FFmpeg 자동 수정 (batch 지원)
→
Verify수정본에 동일 진단 재실행, 통과해야 다운로드
→
ProcessAI 서비스로 전달 (V3: API 연동)

목표 가치: Troubleshooting Time 약 2시간 → 수분. 실제 달성 여부는 운영 데이터(Time to Resolution)로 측정한다.

3. 핵심 기획 판단

① 전부가 아니라 "실패 원인부터" 검사

영상 화질(해상도·blur·noise)까지 검사하면 범위만 커진다. 실제 실패 원인은 음성 채널 조건이었으므로 V1은 Video Integrity를 최소로 두고 Audio Signal Integrity를 핵심으로 설계했다. 이름도 File Validation이 아닌 AI Processing Readiness Check.

② 채널 수는 오류가 아니다

stereo는 정상이다. "Channel = 2 → 경고"는 오탐이다. 봐야 하는 것은 채널 간 상태 이상: 채널별 음량, 무음 비율, 음성 활동, L/R 상관관계, 그리고 모노로 합쳤을 때 음성이 사라지는지.

③ 자동 수정에도 조건을 붙인다 (Exception handling)

무조건 L→L/R 복제는 정상 stereo를 망친다. 근거가 명확할 때만 자동 수정하고, 애매하면 Review Required + 수동 검토로 둔다. "AI가 알아서 고친다"가 아니라 검증된 결정적 변환을 제품화했다.

④ 사실과 가설을 구분한다

확인된 사실: -ac 1(모노 변환) 실패, 정상 채널 복제(pan + -c:v copy) 후 정상 STT. 당시 L/R 측정값이 없으므로 원인을 "위상 상쇄"로 확정하지 않고, 제품도 "가능성 + 측정 근거"로 표현한다.

5. 예외 처리: 자동 수정 조건

Channel Analysis
 ├ L/R 정상            → 그대로 진행
 ├ 한쪽 채널 이상 (근거 명확)
 │  · 한쪽 사실상 무음 (≥20dB 차이, 무음 ≥90%)
 │  · 모노 합산 시 음성 소멸 (손실 ≥10dB)
 │                       → Channel Correction 제안
 └ 판단 불확실 (레벨 차이만 큼, 상관 낮음)
                         → Review Required, 자동수정 없음

6. KPI 구조

North Star  First-Pass Processing Success Rate
 │ 수정·재업로드 없이 유효한 AI 결과가 나온 비율
 ├ Input Quality     Detection Rate / False Positive
 ├ Efficiency        Time to Diagnosis ✓
 │                   Time to Resolution ✓
 │                   Reprocessing Rate
 └ Output Quality    Zero-Output Rate (SUCCESS인데 0건)
                     Verification Pass Rate ✓

✓ = 서비스에서 실제 집계 중. Zero-Output Rate는 System/Business Success 차이를 직접 측정하는 지표.
